# 资源匹配

搜索返回十几条同名结果时，**不能取第一条**。按下面的顺序逐层筛选，任何一层出现"只剩一条"就停下。

## 匹配五要素

| 维度 | 判断方式 | 权重 |
| --- | --- | --- |
| 歌名 | 归一化后完全相同 > 包含 > 相似 | 必要 |
| 歌手 | 完全一致 > 目标歌手在 `artist` 里（合唱/feat）> 部分匹配 | 高 |
| 专辑 | 用户指定了专辑才比；一致则强烈加分 | 中 |
| 版本 | 排除用户没要的 live / 伴奏 / remix / 翻唱 / DJ 版 | 高 |
| 可用性 | `qualities` 非空；能到达要求的档位；平台已登录 | 必要 |

归一化：去空格、全半角统一、去书名号/引号/括号后缀（如 `(Live)`、`【伴奏】`）、英文小写。

## 决策顺序

```
1. 按歌名筛选（必须命中，否则视为没搜到 → 换关键词）
2. 按版本过滤：用户没说 live/伴奏/翻唱/remix，就排除这些标记
3. 按歌手筛选：目标歌手出现在 artist 字段
4. 若用户给了专辑名 → 按专辑收窄
5. 若用户给了音质要求 → 只保留能满足的平台/条目
6. 剩余条数
   ├── 1 条 → 直接用
   ├── 0 条 → 降级：从第 3 步松绑（歌手写错/合作署名不同），或换平台
   └── ≥2 条 → 看是否可自动区分
               ├── 时长/专辑不同但用户没说 → 列 2–3 条让用户选
               └── 完全同质（重复资源）→ 取 qualities 更全的那条
```

## 示例：搜索「晴天」

```
A 晴天 - 周杰伦 · 叶惠美 · 269s · [128kmp3, 320kmp3, flac]
B 晴天 - 周杰伦 · 叶惠美 (Live) · 298s · [128kmp3]
C 晴天 - 某翻唱 · 单曲 · 240s · [128kmp3]
D 晴天 - 周杰伦 · 叶惠美 · 269s · [128kmp3, flac, hires]
```

- 用户说"下晴天" → C 是翻唱，B 是 live，排除；A 与 D 是同一录音 → 取档位更全的 **D**。
- 用户说"要 live 版" → 选 B。
- 用户说"下 320k" → B/C 没这档，A/D 都有 → 取 D（档位更全，后续降级余量更大）。

## 判重（同一录音）

服务端判重不看标题，看 `platform + mid`（`mid` 为空时用 `id`，或 `mediaMid` 命中）：

```
同一首歌 = 同平台 && (mid 相同 || (mid 都空 && id 相同) || mediaMid 相同)
```

所以：

- 不要用标题+歌手自己判重，会漏掉同名不同版本，也会误杀不同平台的正版。
- 跨平台同一首歌**不算重复**，可以都下（音质/完整性可能不同）。
- 拿不准时先 `list_tasks`，看是否已有同 `mid` 的任务，避免撞出 `existing`。

## 同名不同版本的处理

| 提示词 | 处理 |
| --- | --- |
| 未指定 | 排除 live/伴奏/翻唱/remix/DJ，取录音室版 |
| "现场版" / "演唱会" | 只留 `Live` / `Concert` |
| "伴奏" | 只留 `Instrumental` / `伴奏` |
| "翻唱" | 只留非原唱歌手 |
| "原版/录音室版" | 排除全部附加标记 |
| "remix/混音" | 只留 `Remix` / `Mix` |

## 不确定就别下

以下情况必须先问用户，不要猜：

- 剩余 2 条以上且无法自动区分（尤其时长相同但专辑不同）；
- 用户说的歌名只命中"包含"而非"完全相同"，且候选歌手都不是目标歌手；
- 只有低音质可用（如用户要 flac，全部候选最高 128kmp3）；
- 目标平台未登录，其它平台有正版 —— 先说明再问要不要换平台。

提问时给**可选项**而不是开放问题：

> 搜到 3 个"晴天"：① 周杰伦/叶惠美/269s ② 周杰伦/叶惠美(Live)/298s ③ 某翻唱/240s。要下哪个？都没说要 live 的话我默认①。

## 实战：关键词搜索经常搜不到原版

实测（网易云，2026-11-27）搜「周杰伦 晴天」前 10 条：

```
1. 晴天 (原唱 周杰伦)      RyaVocal       ← 翻唱
2. 晴天                   Jay            ← 别名条目，非"周杰伦"署名
3. 晴天                   舟子
5. 晴天 (钢琴版) [原唱: 周杰伦]  纪钧瀚
8. 晴天 (女生版)           余不不
9. 晴天周杰伦(从前从前…)    沈幼楚
10. 晴天                  短音、qwer、qazw…（16 人拼盘）
```

**一条周杰伦原版都没有。** 只靠标题+歌手字符串匹配，要么下错版本，要么判定"搜不到"。

正确做法：**先定位歌手，再取他的歌**。

```
search_artists "周杰伦"            → id 6452（注意别名条目 "Jay" id 122200643 是另一个）
fetch_artist_songs {id: 6452, page: 1, limit: 50}
  → 命中：晴天 | 周杰伦 | 叶惠美 | id 186016 | 128kmp3,320kmp3,flac
```

判断依据换成**歌手 ID 一致**，而不是歌手名字符串相等。名字有别名（Jay / 周董）、有后缀（"周杰伦."）、有拼盘署名，ID 不会。

适用场景：热门老歌、被大量翻唱的歌、名字很短（"晴天""后来""红豆"）。冷门歌用关键词更省事。

## 匹配完的交接

确定唯一后，**不要直接建任务**：

1. 若来自搜索结果 → 先 `parse_link`（或 `songs/detail`）拿真实完整 `qualities`；
2. 走 `quality-selection.md` 选档；
3. 再 `create_download_task`。

原因：搜索结果的档位可能是占位，直接建任务容易落成 `error`（所选音质不可用）或者下到低档。
