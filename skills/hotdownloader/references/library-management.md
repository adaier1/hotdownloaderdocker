# 曲库管理

曲库 = **服务端下载目录里的真实音频文件**，不是任务记录。任务删了文件还在，文件删了任务记录还留着——两者要分开看。

## 查询

```jsonc
list_library {"keyword":"周杰伦","offset":0,"limit":50}
// → {"directory":"…","total":12,
//    "files":[{"name":"晴天.flac","path":"…/晴天.flac","size":32518123,"extension":"flac"}]}
```

- `keyword` 只匹配**文件名**，不匹配标签里的标题/歌手。找某歌手就先按歌手名筛文件名（下载时文件名通常含歌手）。
- `total` 是过滤后的总数，`limit` 最大 500；文件很多时分页取，不要一次拉全量。
- HTTP 的 `GET /api/library` **不支持过滤分页**，大目录用 MCP。

统计用途：按 `extension` 分组算格式分布、按 `size` 找可疑的小文件（试听片段常只有 1–2MB）。

## 删除

```jsonc
delete_library_files {"paths":["…/晴天.flac"]}
// → {"deleted":1,"failed":[{"path":"…","error":"…"}]}
```

- 只接受 `list_library` 返回的路径；服务端会剥离目录只取文件名再拼回下载目录，**传任意路径也删不到目录外**。
- 非音频扩展名会被拒绝。
- `failed` 是数组（每项 `path` + `error`），不是数量。

**删除前必须确认**：列出文件名、数量、总体积，等用户明确同意。批量删除一次不超过 50 个，分次确认。

## 重命名

```jsonc
rename_library_file {"path":"…/晴天.flac","newName":"周杰伦 - 晴天"}
```

- `newName` 只传文件名，不要带目录。
- 可省略扩展名，服务端沿用原扩展名。
- `\ / : * ? " < > |` 会被替换成下划线。
- 目标名已存在时返回错误，不会覆盖。
- **只有 MCP 有这个能力**，HTTP 没有。

批量改名（如统一成 `歌手 - 歌名`）：

1. `list_library` 拿全量；
2. 解析现有文件名，生成新名（无法解析的跳过，列给用户）；
3. 逐条 `rename_library_file`，失败的收集；
4. 报告改了几个、跳过几个、失败几个。

不要在没看现有文件名规律的情况下批量改名——有的用户已经手工整理过。

## 写标签

```jsonc
write_library_metadata {
  "path":"…/晴天.flac",
  "title":"晴天","artist":"周杰伦","album":"叶惠美",
  "lyrics":"[00:00.00]…"
}
```

- 只改传入的字段；传空字符串表示**清除**该字段。
- 支持 `title` `artist` `album` `lyrics`；不支持自定义字段、封面（封面由下载时的 `downloadCover` 设置决定）。
- 同样**只有 MCP 有**。
- 写标签会重写文件，正在播放/被占用的文件会失败——提示用户关掉播放器。

## 去重

服务端没有"按内容去重"的能力，做的是**清单式人工确认**：

```
1 list_library 全量
2 按 归一化(歌手 + 标题) 分组
3 每组 ≥2 个文件 → 候选重复
4 比较 size 与 extension：
    - 同扩展名、size 相差 < 2% → 高度疑似重复（保留一个）
    - 扩展名不同（flac + mp3） → 不是重复，是两种格式，问用户要留哪个
    - size 差异大 → 可能是不同版本（live/伴奏），列出来让用户判断
5 输出清单 → 用户确认 → delete_library_files
```

去重报告示例：

```
疑似重复 3 组（未删除）：
1. 晴天.flac (31MB) / 晴天 (1).flac (31MB) —— 建议保留前者
2. 七里香.flac / 七里香.mp3 —— 两种格式，要留哪个？
3. 稻香.flac (28MB) / 稻香 (Live).flac (33MB) —— 不同版本，都不动

确认要我删第 1 组里的 "晴天 (1).flac" 吗？
```

## 整理建议（用户说"帮我理一下"时）

按这个顺序做，每步都先给方案再执行：

1. **孤儿文件**：文件名里没有歌手信息、或明显是临时文件（`.part`、`.tmp` 不会被列出，因为不是音频扩展名）；
2. **格式统一**：同一首歌多种格式并存 → 按音质偏好留一个；
3. **命名统一**：`歌手 - 歌名.ext`，注意有些平台的默认命名是 `歌名 - 歌手`；
4. **标签补全**：文件名能解析出歌手/歌名的，写进标签；
5. **真重复**：同格式同大小。

不要自动决定"哪个好听"，一切以用户确认为准。

## 与任务的关系

| 想知道 | 查哪里 |
| --- | --- |
| 这首歌下过没 | `list_library` 看文件名；或 `list_tasks` 看有没有 `completed` |
| 文件在哪 | 任务的 `filePath`；或 `list_library` 的 `path` |
| 删了任务文件还在吗 | 在。`remove_task` 默认 `deleteFile: false` |
| 下过但曲库没有 | 文件被手工移走/改了扩展名，`list_tasks` 仍显示 completed |

用户说"重新下载"之前，先查曲库——很多时候文件已经在了，只是不在默认目录里。
